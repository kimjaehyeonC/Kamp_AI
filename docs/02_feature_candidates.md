## 최종 모델 피처 — 6개 → 4개 → 3개로 축소 (`05_oneclass.ipynb`)

03·04에서 쓰던 6개(`ai0_rms, ai1_rms, cur_ai0_resid, cur_ai1_resid, ratio_ai1_ai0,
normal_center_nrmse`)에 **공선성 점검을 하지 않고 있다가**, 사용자 지적으로 확인했더니
구조적 중복이 있었다.

**발견: `cur_ai0_resid`·`cur_ai1_resid`·`ai0_rms`·`ai1_rms` 4개가 정확한 선형 제약으로
묶여 있다.** 두 잔차 모두 같은 `cur_rms`를 regression으로 빼서 만들었기 때문에
(`cur_ai0_resid = ai0_rms - (slope0·cur_rms + b0)`, AI1도 동일 구조), `cur_rms`를
소거하면 이 4개 사이에 정확히 하나의 선형식이 남는다 — VIF 측정 결과 이 4개 전부
`R²=1.000(다른 5개로 완전 예측)`, raw 공분산 조건수 **1.29×10¹⁸**(사실상 특이행렬)로
확인됐다. `ratio_ai1_ai0`(=ai1_rms/ai0_rms)도 둘과 강하게 종속된다(VIF 40.65). 상관행렬
고유값도 이를 뒷받침한다: `[3.288, 1.773, 0.858, 0.069, 0.012, 0.000]` — 마지막이 정확히
0, 즉 6개 중 1개 방향은 완전히 결정론적이다.

### 1차 결정(4개) — 수동 선택이었음

처음에는 비대칭성 논리로 수동 선택했다: AI0-전류 상관이 약해서(0.645) `cur_ai0_resid`는
`ai0_rms`와 거의 같고(corr 0.764, 잔차의 의미가 적음), AI1-전류 상관이 강해서(0.968)
`cur_ai1_resid`는 `ai1_rms`와 거의 다른 정보였다(corr 0.252). 단독 AUC도 `ai0_rms` 0.898 >
`cur_ai0_resid` 0.853이라 `cur_ai0_resid`·`ratio_ai1_ai0`만 빼고 4개(`ai0_rms, ai1_rms,
cur_ai1_resid, normal_center_nrmse`)로 축소했다.

이 수동 선택이 **6개 중 유일한 정답인지는 확인하지 않은 채** 넘어갔다는 지적을 받아
(사용자: "공선성 점검파트에서 6개중 어디까지 축소할지는 확인해야할거같네요"), 자동화된
검증이 필요했다.

### 2차 결정(3개) — 단계적 VIF 제거로 재결정, 블록 k-fold는 검증에만 사용

수동 선택 대신 **단계적 VIF 제거**(매 단계 VIF 최댓값인 피처를 하나씩 제거, VIF<10에서
중단 — 성능과 무관한 구조적 기준)를 돌리자 다른 조합으로 수렴했다:

```
[6개] cond=1.29e+18  최대VIF=ai0_rms(inf)
[5개] cond=2.14e+04  최대VIF=ai1_rms(41.3)
[4개] cond=1.39e+04  최대VIF=ratio_ai1_ai0(10.5)
[3개] cond=2.55e+00  최대VIF=cur_ai1_resid(1.2)  <- 중단
최종: cur_ai0_resid, cur_ai1_resid, normal_center_nrmse
```

**피처는 이 VIF 결과만으로 확정했다.** 처음에는 4개(수동)와 3개(자동)가 단일 분할에서
test_FP=0/109·outlier_TP=17/17로 동률이라 6-fold CV로 둘을 성능 비교해 더 나은 쪽을
고르려 했으나, 이는 `03_modeling_strategy.md`의 "평가 보강 사항" 합의와 다른 용법이었다
— 그 합의는 **단일 60/20/20 분할 대신 블록 k-fold로 (이미 정해진) 모델의 오경보율에
신뢰구간을 붙이자**는 것이었고, 피처 후보를 성능으로 가려내는 도구가 아니었다. 성능으로
피처를 고르고 그 성능을 다시 신뢰구간으로 보고하면 같은 데이터를 두 번 써서 결과가
낙관적으로 편향된다(post-selection inference). 그래서 **선택은 VIF로 끝내고, CV는
VIF가 고른 최종 3개 모델만 검증**하는 것으로 정정했다.

**최종 채택: `cur_ai0_resid, cur_ai1_resid, normal_center_nrmse` (3개), 선택 근거는 VIF뿐.**

```
최종 3개: cur_ai0_resid, cur_ai1_resid, normal_center_nrmse
```

| 지표 | 6개 | 4개(수동, 1차) | 3개(자동, 최종) |
|---|---:|---:|---:|
| raw 공분산 조건수 | 1.29×10¹⁸ | 131.0 | **2.55** |
| Mahalanobis validation/test 오경보(단일 분할) | 0/109 | 1/109(seg529) | **0/108, 0/109** |
| Mahalanobis outlier 탐지(단일 분할) | 17/17 | 17/17 | **17/17** |

3개로 줄이면서 4개의 유일한 오경보(seg529, n=11)까지 사라져 Mahalanobis가 단일 분할
기준 validation·test 모두 FP 0%/TP 100%가 됐고, 조건수도 131→2.55로 한 번 더
정상화됐다(LedoitWolf 축소추정이 거의 불필요한 수준).

### 모델 검증(블록 k-fold) — 세 모델 전부에 공정하게 적용

처음 버전은 이 k-fold CV를 Mahalanobis 한 모델에만 돌렸다. "모든 모델이 공정한 평가를
받아야 한다"는 지적을 받아, **시간순 6블록 블록 k-fold**(무작위 대신 시간 블록인 이유:
V자 드리프트 01:00~01:17 구간을 특정 폴드가 통째로 못 보고 평가받게 하려고 — 폴드5가
이 구간과 거의 겹친다)를 **Mahalanobis·Isolation Forest·One-Class SVM 세 모델 모두**에
동일하게 적용했다(`05_oneclass.ipynb` ## 6-1절, 하이퍼파라미터는 각 모델의 기존 절에서
고정한 값과 동일):

| 모델 | FP 평균 | FP sd | FP 95% CI | TP 평균 | TP sd |
|---|---:|---:|---:|---:|---:|
| Mahalanobis | 0.19% | 0.46%p | [0.00%, 0.55%] | **100%** | 0 |
| Isolation Forest | 0.19% | 0.46%p | [0.00%, 0.55%] | **95.1%** | 2.4%p |
| One-Class SVM | 0.37% | 0.92%p | [0.00%, 1.11%] | **100%** | 0 |

FP는 세 모델 다 낮고 신뢰구간이 겹친다 — 단일 분할에서 셋 다 FP 0%였던 것이 폴드 평균과
같은 범위라, 과적합된 운 좋은 샘플은 아니었다. **TP에서 모델 간 차이가 드러난다**:
Mahalanobis·One-Class SVM은 모든 폴드 100%(sd=0)인데 Isolation Forest는 평균
95.1%(sd 2.4%p)로 폴드마다 흔들린다.

**흥미로운 발견**: 이 95.1%는 단일 60/20/20 분할의 test TP 76.47%(13/17, 피처 4→3개
단계에서 15/17→13/17로 떨어졌던 그 수치)보다 훨씬 높다. 즉 단일 분할에서 Isolation
Forest가 유독 나빴던 건 그 특정 train 샘플에서 우연히 안 좋게 학습된 결과였고, 6개
폴드 평균이 실제 성능에 더 가깝다 — **모델 하나만, 혹은 단일 분할로만 보고하면
오해할 수 있다는 직접적인 증거**다.

**결론: 채택 모델(Mahalanobis)이 TP 100%/sd 0, FP 0.19%로 여전히 최상이고, One-Class
SVM도 TP는 동일하게 완벽해 사실상 공동 1위다.** Isolation Forest는 fold 평균으로도
TP가 더 낮고 분산이 있어 세 모델 중 가장 불안정하다 — 단일 분할만 봤을 때의 결론(IF가
3개 중 가장 나쁘다)과 방향은 같지만, 격차의 크기는 fold 평균이 더 신뢰할 만한 추정이다.
SHAP·D² 기여도 분해 결론(`normal_center_nrmse` 압도적 1위, `cur_ai1_resid`는 seg19·20
"조용함" 유형 전용)은 6개→4개→3개 내내 동일하게 유지된다.
