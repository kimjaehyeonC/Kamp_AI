# 03 — 모델 학습·평가 전략

## 기본 단위와 데이터 분할

- 원시 시계열을 먼저 세그먼트로 나누고, **세그먼트 1개를 하나의 cycle 표본**으로 사용한다.
- 인접 세그먼트는 서로 유사하므로 무작위 분할하지 않고 **시간순 연속 블록**으로 나눈다.
- 정상 데이터는 앞 60%를 train, 다음 20%를 validation, 마지막 20%를 test로 사용한다.
  - train: 피처 기준·스케일러·모델 학습
  - validation: threshold와 `N개 중 M개` 경보 규칙 설정
  - test: 정상 오경보율 최종 평가
- 현재 outlier는 별도 시점의 단일 이상 에피소드다. 세그먼트를 무작위 분할하기보다 시간순
  그대로 투입해 cycle 단위 이상 탐지율과 미탐률을 평가한다.

현재 유효 피처는 outlier를 참고해 선택했으므로 해당 outlier 성능은 완전한 외부 검증이 아니라
**공모전 개발 데이터 내 성능**으로 해석한다. 이 한계는 감안하되, 확보된 이상 징후를 최대한
활용해 모델을 비교한다.

## 모델링 우선순위

1. `normal_center_nrmse` 단일 threshold를 기준선으로 둔다. **(04 종료)** `04_rule_base.ipynb`는
   05와 동일한 3개 피처로 fold 기준 재평가를 마치고 종료한다 — 피처를 고정해도 OR
   결합은 Mahalanobis보다 FP가 3~8배 높아(1.51%/0.57% vs 0.19%), 04의 한계가 피처
   집합이 아니라 OR 결합 자체(공분산 미사용)임을 확인했다. 이후 피처 추가·개선은
   전부 05(oneclass) 계열에서만 진행한다.
2. `band_purity`, 진동 RMS·자기상관, `env_cv`, `ai1_peak_hz`, `cur_vib_resid` 등을 결합한
   one-class 모델(Mahalanobis, Isolation Forest, One-Class SVM)을 비교한다.
3. 공모전용 비교군으로 정상·이상 피처를 함께 쓰는 Logistic Regression, SVM 등 단순
   지도학습 모델도 평가한다. 이상 표본이 적으므로 복잡한 모델의 과적합에 주의한다.
4. ~~cycle 이상 점수에 **최근 N개 중 M개 초과** 규칙을 적용해 일시적 오경보를 줄인다.~~
   **기각(05-1에서 확인)**: 이 데이터엔 연속 오탐/미탐이 없어(모든 모델, 모든 연속
   런 길이=1) 규칙이 가정하는 실패 모드 자체가 존재하지 않는다. 적용하면 조기성만
   N사이클만큼 깎이고 얻는 게 없어 채택하지 않는다.
5. 딥러닝은 주력이 아니라 비교 실험으로 둔다. `06_window_latency.ipynb`에서 확인한 대로,
   통계 모델을 1.0초(10샘플) 윈도우로 절단해도 전체 사이클과 동일한 성능이 나와 남은
   여지가 1.0초 아래의 좁은 구간뿐이므로, LSTM/CNN 비교는 **"그 구간을 더 당길 수
   있는가"**로 목표를 좁혀 진행한다(`07_deep_window.ipynb`, 미착수).

## 공통 평가 지표

이상을 양성으로 정의하고, 모든 모델을 동일한 평가 표본과 기준으로 비교한다.
정상 test와 학습에 사용하지 않은 outlier에서 아래 다섯 지표를 보고한다.

| 지표 | 계산 | 평가 데이터 |
|---|---|---|
| 정상 탐지율(정상 판정률) | TN / (TN + FP) | 정상 test |
| 이상 탐지율 | TP / (TP + FN) | outlier |
| 오경보율 | FP / (TN + FP) | 정상 test |
| 미탐률 | FN / (TP + FN) | outlier |
| Balanced Accuracy | (정상 탐지율 + 이상 탐지율) / 2 | 두 평가 데이터 종합 |

비율과 함께 판정 건수·분모를 표시한다. 정상 탐지율과 오경보율, 이상 탐지율과 미탐률은
각각 합이 100%다. 모델 선정은 **허용 오경보율을 만족하는 모델 중 이상 탐지율**을 우선하고,
Balanced Accuracy로 종합 성능을 비교한다. 단일 NRMSE 기준선 대비 개선 여부도 확인한다.
F1, AUC, 시간당 오경보 수, 에피소드 탐지 여부·최초 경보 지연 등 추가 지표는 추후 검토한다.

## 평가 보강 사항

- 60/20/20 단일 분할 외에 블록 k-fold 또는 부트스트랩으로 오경보율에 신뢰구간을 붙인다.
  표본이 작아 점추정만으로는 모델 간 차이를 판단하기 어렵다.
- 전환구간(00:55~01:17, 진입/저점/복귀) 점수를 시간축에 그대로 플롯해 경계에서 점수가
  급변하는지 진단한다. fold 분할과 별개로, train/test 구분 없이 확인한다.
- 세그먼트 단위 회귀테스트를 둔다: seg3·19·20(미탐 후보), n≈23 부근(오탐 후보)을 모델마다
  개별 확인한다. 집계지표에 묻히지 않도록 한다.
- 세그먼트 길이 구간별로도 분해해서 평가한다. rms 계열은 n=10~19에서 분리력이 크게
  떨어진 전례가 있다. 새 모델이 같은 구간에서도 같은 문제를 겪는지 확인한다.

**진행 현황(`05_oneclass.ipynb` ## 6-1)**: 블록 k-fold를 Mahalanobis·Isolation Forest·
One-Class SVM **세 모델 모두**에 동일하게 적용해 FP/TP에 신뢰구간을 붙였다(한 모델만
검증하면 "모든 모델을 동일한 기준으로 비교한다"는 위 원칙과 맞지 않으므로, 처음에
Mahalanobis만 검증했던 버전을 세 모델로 확장했다). 결과: FP는 세 모델 다 낮고 신뢰구간이
겹친다(Mahalanobis·IF 평균 0.19%, SVM 0.37%). TP는 Mahalanobis·SVM이 모든 폴드 100%인데
Isolation Forest는 평균 95.1%(sd 2.4%p)로 흔들린다 — **그런데 이 95.1%가 단일 60/20/20
분할의 test TP(76.47%)보다 훨씬 높아, 단일 분할 점추정만 봤으면 IF를 실제보다 나쁘게
평가했을 뻔했다.** 이 사례 자체가 첫 번째 항목(신뢰구간 필요성)의 실증 근거다.

**진행 현황(`05_oneclass_fp_analysis.ipynb`)**: 두 번째 항목(전환구간 진단)을 완료했다.
정상 전체(train+validation+test, 530개)를 시간순으로 스캔한 결과 held-out(validation+
test) FP는 Mahalanobis·IsolationForest 0건, One-Class SVM 1건(seg437, 전환구간 진입
시점 00:55:11, n=10으로 짧은 사이클)이다.

세 번째 항목(세그먼트 단위 회귀테스트)도 갱신했는데, **단일 60/20/20 분할 모델만으로는
결론이 틀릴 수 있다는 것까지 함께 확인했다.** 처음엔 그 모델 하나로 IsolationForest의
미탐이 seg3·15·19·20 네 개로 보였다(seg15가 기존 하드케이스 목록에서 빠져 있었다).
그런데 6-fold 각각 독립 학습한 모델로 같은 outlier를 다시 채점하니, **실제로 항상(6/6)
놓치는 건 seg3 하나뿐**이고 나머지 셋(15·19·20)은 전부 6/6으로 안정적으로 잡혔다 — 단일
분할의 특정 train 샘플에서만 우연히 놓친 것이었다. "조용함 유형(음의 `cur_ai1_resid`)이
미탐과 연결된다"던 해석도 이 재검증으로는 뒷받침되지 않는다. 진짜 구조적 미탐(seg3)의
특징은 3개 피처 중 `normal_center_nrmse` 하나에서만 이상(z≈80)이고, 그마저도 다른
outlier(z 110~290)보다 덜 극단적이라는 점이다.

네 번째 항목(길이 구간별 분해)도 갱신했다 — 지금까지는 `n≥10`만 평가하고 그 아래는
"판정 보류"로 뒀는데, **그 보류 구간(정상 11.5%, outlier 19%)을 fold 기준으로 실제
판정시켜보니 Mahalanobis 오탐률이 32.2%까지 뛴다**(One-Class SVM 42.4%, Isolation
Forest만 6.8%로 비교적 안정). **04의 rule-base도 같은 구간에서 오탐률 18.6~40.7%로
무너지고, `nrmse_only`는 짧은 outlier를 5/24나 놓친다** — 04부터 05까지 전부 같은
문제를 공유하므로, 이건 모델 선택의 문제가 아니라 `normal_center_nrmse` 자체가 짧은
사이클에서 통계적으로 불안정해지는 근본 문제다. n≥10에서는 거의 완벽했던 채택 모델이
짧은 사이클에서는 전혀 안전하지 않다는 뜻이고, `02_feature_candidates.md`의 "n<10
별도 처리, 지금은 보류" 항목이 더 이상 보류일 수 없다는 근거가 됐다. n=1(정상 9개)은
`normal_center_nrmse` 계산 자체가 안 되어(NaN) 어느 모델·규칙으로도 판정 불가능하다.

**대응(`05_oneclass.ipynb` ## 8)**: 원인이 `normal_center_nrmse`의 추정 불안정성이므로,
n=2~9 전용으로 그 피처를 빼고 `cur_ai0_resid`·`cur_ai1_resid` 2개만 쓰는 Mahalanobis를
따로 학습했다. 오탐률이 32.2% → **3.3%**로 떨어지고 탐지율은 100%를 유지한다. 원시
RMS(`ai0_rms`/`ai1_rms`/`cur_rms`)로 바꿔보면 오히려 탐지율이 0%로 전부 실패 — 짧은
창에서는 사인파의 위상을 어디서 포착했는지가 RMS 값을 지배해 신호가 거의 안 남고,
잔차(두 RMS의 차)만 그 공통 위상 노이즈를 상쇄해 살아남는 것으로 보인다. **모델링
방향을 2-track으로 확정**: n≥10은 기존 3개 피처 Mahalanobis, n=2~9는 2개 피처(잔차만)
전용 Mahalanobis, n=1은 계산 불가로 판정 보류. n=2~9 모집단이 작아(정상 60·outlier 4)
추정이 n≥10만큼 안정적이지는 않다는 한계는 남는다.
