결과 사이클 시작 후 **1.0초(샘플 10개)만 봐도 전체 사이클(최대 4.9초)과 동일한
성능**(오경보 0%, 탐지율 100%)이 나온다(`06_window_latency.ipynb`). N중M 지속성
규칙은 쓰지 않는다 — 연속 오경보가 한 건도 없어 걸러줄 대상이 없고, 쓰면 경보만
늦어진다.

## 사전경보 + 점검 우선순위

Mahalanobis 점수가 임계(5.42)를 넘으면 1.0초 안에 경보하고, D² 기여도 분해로
원인 피처를 바로 제시해 점검 범위를 좁힌다.

| D² 1위 피처 | 의심 현상 | 점검 우선순위 |
|---|---|---|
| `normal_center_nrmse` 단독 | 전류 파형 이상 | 전류 계통(모터·드라이브) |
| `cur_ai0_resid` 동반("시끄러움") | 전류 대비 상부진동 과다 | 상부 진동원(베어링·체결부) |
| `cur_ai1_resid` 동반("조용함") | 하부진동-전류 결합 끊어짐 | 하부 구동계·커플링(놓치기 쉬운 유형) |

## 세그먼트 길이별 처리

| 길이 | 처리 |
|---|---|
| n≥10 | 자동 판정, 즉시 경보 |
| 2≤n<10 | 전용 2피처 모델 판정, 경보 시 **작업자 확인 요청**(오경보율 3.3%로 상대적으로 높음) |
| n=1 | 판정 불가 → 보류 + 작업자 확인 |

사이클의 88.5%(n≥10)는 완전 자동화, 나머지 11.5%만 작업자가 개입한다.

```
사이클 시작 → 1.0초 경과(또는 조기 종료)
  n≥10 → Mahalanobis(3피처) → 경보 시 D²분해 원인제시 → 즉시 경보
  2≤n<10 → 전용 2피처 모델 → 경보 시 작업자 확인 요청
  n=1 → 보류 → 작업자 확인
```
